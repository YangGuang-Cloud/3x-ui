搬瓦工周期用量与客户端占比

仅在 main 开发；Release 推送仍是正式部署动作。本功能默认关闭。
本地验收地址：http://127.0.0.1:18090/panel/clients

功能入口
- 概览与客户端列表顶部：搬瓦工本周期用量、剩余额度、下一次重置时间、本面板客户端总计。
- 客户端列表：本周期用量 / 套餐额度、客户端内流量占比、上下行标称带宽占比；移动端卡片同样支持。
- 统计设置：VEID、API Key、上下行标称 Mbps。0 表示未知，显示 —，不猜测带宽。
- 官方 API 无已列出的套餐带宽上限字段，带宽参照值需从套餐确认后填写。

实际核对来源（2026-10-23）
用户已登录的 KiwiVM 官方 API 页：
https://kiwivm.64clouds.com/2022542/main-exec.php?mode=api
getServiceInfo 提供 plan_monthly_data、data_counter、monthly_data_multiplier、data_next_reset。
按照官方说明，对 quota 与 used 都应用 multiplier（允许小数）。实际返回值与 KiwiVM 1000 GB 套餐匹配。
官方 Available calls 中没有主动重置套餐流量的调用。不调用 VPS restart/reset 等控制接口。
只向固定 https://api.64clouds.com/v1/getServiceInfo 发 POST，禁止重定向，超时 20 秒，响应上限 1 MiB。
每 5 分钟最多查询一次（手动同步也遵循此缓存），失败保留最后一次成功值并显示过期/错误。

周期与清零语义
- 第一次接入不把历史累计量冒充当月用量，明确标为“接入以来”。
- 仅当供应商 next_reset 向未来推进，且上一重置时刻已经到达时，创建新周期。
- 新周期从上一重置时间开始，本地总计和各客户端周期用量自然重新计数；旧周期与历史流量保留。
- 到时 API 尚未更新、失败、时间倒退或提前改变重置日期时，不清零，不改客户端配额。
- 长时间离线跨过无法确认的多个月时从重新接入计数，标注不完整。
- 重新启用统计后覆盖不全的周期标注不完整。
- 时间显示按浏览器时区，按 API 的 Unix 时间戳处理，不按每月 1 日或 KiwiVM 日期标签猜测。
- 本地代理流量按分钟记录和归属，边界附近可能有不足一分钟的归属误差。
- 统计仅含该面板本机核心报告的代理流量，不含远程节点流量。
- 套餐流量包含其他业务、网络开销，客户端用量不能视为精确的供应商账单分摊。
- 原配额计数、重置策略、限速、已用额度、到期和核心配置都保持原有语义；本功能不重启核心。

数据与凭据
- 新增数据库表 bandwagon_cycles、bandwagon_traffics，均加入初始化与迁移注册表。
- 用稳定 client_id 关联用量，改名不丢历史；删除后重建相同邮箱不会继承旧客户端占用。
- 分页列表增加 id 字段，其他现有返回字段不变。
- 辅助统计写在主流量事务提交后；辅助写入失败不会回滚主配额计数，页面显示统计可能不完整。
- 凭据：XUI_DB_FOLDER/bandwagon.json，原子写入，0600 权限，不在通用设置 JSON 或 API 响应返回密钥。
- API：GET /panel/api/bandwagon；POST /panel/api/bandwagon/config；POST /panel/api/bandwagon/sync。
- 路由使用面板现有登录/管理员令牌鉴权及 CSRF；monitor/node-sync 令牌不具备这些权限。
- 本地 .cache/local-dev/db/bandwagon.json 被 Git 忽略，不进入发布包。正式上线后需单独配置正式面板。
